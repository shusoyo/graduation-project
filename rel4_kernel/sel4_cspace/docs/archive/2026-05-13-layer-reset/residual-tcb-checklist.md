# Residual TCB Checklist

本清单对应当前这轮 `contract-first` sweep，目标不是立刻把所有 residual trusted helper 证明掉，而是先把边界显式化：

- semantic and contract calibration from `l4v`
- Verus organization from `atmo`

分类固定为三类：

- `Permanent bridge`: 表示桥、pointer/perm bridge、bitfield/hardware/FFI observer，长期允许保留为 TCB
- `Temporary semantic TCB`: 当前先保留为 trusted helper，但必须有清楚的 `requires/ensures`，后续继续 shrink
- `Internal proof detail`: 纯局部 proof packaging，不单独对外承诺公共 contract

`Contract status` 的含义：

- `missing`: 仍缺少 caller 可直接消费的显式 contract
- `weak`: 已有 contract，但 semantic post / frame / wf 边界还不够清楚
- `acceptable`: 当前 contract 已能支撑 caller 不再依赖黑箱直觉

当前验证基线：

- 本轮全包 direct Verus checkpoint 已推进到 `462 verified, 0 errors`
- `delete` / `swap` 的 no-two-cycle closeout 和 `reduce_zombie(false)` swap-exact projector 已通过 single-point 验证，并纳入全包 checkpoint
- `aarch64` 源码侧 shrink 已落地，但 arm-target 专门验证仍受当前环境限制，因此这一项继续按环境阻塞单独记录

## Current Sweep Exit Criteria

当前这轮 sweep 的收口口径固定为：

- 目标模块里的 residual naked helper 都必须有清楚的 `requires/ensures`，或者被明确记录为 `weak`
- caller 必须只依赖 contract，而不是 helper 黑箱直觉
- 不为了补 contract 新增高层 semantic trusted bridge
- `manager-level verified core`、`public wrapper boundary`、`whole-kernel / l4v-level strength` 三层 claim 继续分开说

当前状态：

- 以上口径在当前目标模块上已经满足。
- 因此当前剩余工作不再是“先把裸函数 contract 化”，而是“继续从 checklist 里挑 residual semantic TCB 做下一轮 shrink”。
